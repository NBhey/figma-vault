# Проверка качества восстановления

Дата: 2026-09-22. Фикстура: `EXAMPLE1234_1_1` (`Sign in / Mobile`).

## Сценарий

Экран был восстановлен в самостоятельный HTML только из данных, доступных MCP-клиенту:

1. `vault_list` — выбор документа;
2. `vault_get_doc(maxDepth: 0)` — размер корня и семь верхнеуровневых блоков;
3. `vault_get_node` — содержимое Brand, Heading, Form, Submit button, Divider и Footer;
4. `vault_get_tokens` — цвета и типографика;
5. `vault_get_asset` — `logo.svg`, `hero.png` и эталонный `screenshot.png`.

Проход всех шести инструментов через настоящий MCP-клиент и `InMemoryTransport` закреплён
в `src/mcp/server.test.ts`. Во время этой проверки восстановленный HTML отдельно отрендерен
headless Chrome в viewport 375×812 и визуально сопоставлен с эталоном того же размера.

восстановились из `doc.json` без догадок. Текст был выведен реальным содержимым из `text.content`.

## Ограничение эталона

Текущая фикстура намеренно синтетическая: в `screenshot.png` вместо глифов текста нарисованы
одноцветные прямоугольники. Поэтому полный pixel-diff дал бы ложную ошибку именно там, где HTML
правильно показывает «С возвращением», подписи полей и остальные строки. Для этой фикстуры
проверяем геометрию блоков, цвета и ассеты; pixel-perfect метрику следует включать на реальной
выгрузке, где screenshot получен Figma API.

## Вердикт

**PASS для MVP.** Контекста шести MCP-инструментов достаточно, чтобы агент восстановил
семантический HTML и все восемь ключевых прямоугольников без доступа к Figma и `raw.json`.
Оставшийся риск — пиксельная точность сложных эффектов и шрифтов на реальных макетах; он уже
видим агенту через `vault_get_asset(..., "screenshot.png")` и не требует участия человека-посредника.

## Структурная сверка в 0.1.1

Команда `figma-vault verify` сравнивает сохранённый `doc.json` со снимком DOM,
полученным скриптом `figma-vault verify <docId> --snippet` в браузере агента.
Все видимые тексты проверяются с учётом повторов и пробелов. Геометрия сверяется
только для явно сопоставленных элементов с `data-figma-node-id`: координаты от
верхнего левого угла корня, допуск по умолчанию — 2 px. Скрытые узлы и их потомки
не являются ожидаемым содержимым страницы. Без сопоставленного корня и хотя бы
одного вложенного блока результат `INCOMPLETE`, а не ложный `PASS`.

2026-09-23 ядро и CLI проверены автоматическими тестами на `PASS`, `FAIL` и
`INCOMPLETE`. Дополнительно в headless Edge при ширине viewport 1280 px был
запущен существующий `restored/portfolio/index.html` против реальной выгрузки
`BTPuYlwkPTzJnLgVcJPetE_0_3`. Только на время проверки в DOM были сопоставлены
корень и семь крупных секций; исходный HTML не менялся. Итог: **FAIL** — все 60
видимых текстов найдены, но у восьми проверенных блоков есть геометрические
расхождения. Например, hero начинается на 81 px ниже Figma, а ширина корня
составляет 1265 вместо 1280 px из-за вертикальной полосы прокрутки. Сверка
обнаружила существующее отличие вёрстки от макета; исправление самой страницы
не входит в релиз инструмента 0.1.1.

`PASS` означает совпадение текстов и *сопоставленных* блоков, а не всех
элементов и не pixel-perfect совпадение. Чтобы увеличить покрытие, агенту нужно
разметить дополнительные значимые блоки их id из `doc.json` и повторить снимок.
