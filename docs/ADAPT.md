# Как доработать под дизайн-систему проекта

Этот документ написан для AI-агента, которого попросили приспособить `figma-vault`
к конкретному проекту. Предполагается, что вы видите кодовую базу проекта, а автор
инструмента — нет.

## Что уже даёт инструмент

После `figma-vault add <ссылка>` на диске лежит `doc.json` со схемой `figma-vault/doc@0`
([docs/CONTRACT.md](CONTRACT.md)). Интересует поле `tokens`:

```json
"tokens": {
  "colors":  { "Gray/400": "#9CA3AF" },
  "text":    { "Input/Default Medium": { "font": "Inter", "size": 15,
               "weight": 500, "lineHeight": 18.15, "letterSpacing": 0.08 } },
  "effects": { "Drop Shadow/xs": "0px 1px 1px 0px rgba(0,0,0,0.05)" }
}
```

Имена — это имена **из Figma**. Если в файле есть shared styles, приедут они.
Если нет, имена будут с префиксом `inferred/` и собраны из фактически повторяющихся
значений: `inferred/color/11d452`. Такое имя годится как опора, но в коде его быть не должно —
переименуйте по смыслу использования.

Каждый текстовый узел может ссылаться на токен через `text.token`, при этом конкретные
значения в узле тоже заполнены. Резолвить токены необязательно.

## Куда встраиваться

`scripts/tokens-to-css.mjs` — **референсная реализация**, а не то, что нужно проекту.
Она читает `doc.json` и пишет CSS-переменные плюс классы `.t-<токен>`. Копируйте подход,
меняйте цель вывода.

Возможные цели, выберите по проекту:

| стек | что генерировать |
|---|---|
| Tailwind | `theme.extend` в `tailwind.config`: `colors`, `fontSize` с кортежем `[size, {lineHeight, letterSpacing, fontWeight}]`, `boxShadow` |
| CSS-модули | глобальный `tokens.css` с `:root{--…}`, модули ссылаются на переменные |
| styled-components / Emotion | объект темы в `.ts` с типами, `ThemeProvider` |
| дизайн-токены уже есть | **ничего не генерировать** — сопоставить имена Figma с существующими и отдать агенту таблицу соответствия |

Последняя строка важнее остальных. Если в проекте уже есть система токенов, второй
параллельный набор — вред. Правильный результат в этом случае — не генератор, а карта
соответствия, которую агент использует при вёрстке.

## Обязательные детали, на которых легко ошибиться

1. **`letterSpacing` не игнорировать.** В реальных макетах он ненулевой почти везде
   (0.05–0.12px). Без него вёрстка выглядит «не тем шрифтом», хотя шрифт верный.
2. **`lineHeight` приходит в пикселях**, не множителем. Переводить в `line-height: Npx`
   или делить на размер самостоятельно.
3. **Порядок `children` — это z-order Figma, а не визуальный.** Секции страницы
   восстанавливаются сортировкой по `layout.y`. Без этого страница соберётся вперемешку.
4. **`layout.mode: row|column`** — это auto-layout, ему соответствует flex с указанными
   `gap` и `padding`. При `mode: none` позиционирование абсолютное по `x/y/w/h`
   относительно родителя.

## Как целиться в компоненты, а не в голый HTML

Восстанавливать макет в размётку с нуля почти всегда неправильно: в проекте уже есть
кнопки, поля, карточки. Порядок, который даёт вменяемый результат:

1. Прочитать макет через MCP (`vault_get_doc` с небольшим `maxDepth`, затем `vault_get_node`).
2. Найти в проекте существующие компоненты, покрывающие увиденные узлы.
3. Сопоставить: узел `Input` из макета → компонент проекта; узел `Radio card` → компонент.
4. Верстать композицией существующих компонентов, новые заводить только там, где аналога нет.
5. Отдельно перечислить, что пришлось завести с нуля, — это повод дополнить дизайн-систему.

Текст слэш-команды `/figma`, который создаёт `figma-vault init`, лежит в
`src/cli/init.ts` (константа `SLASH_COMMAND`). Под проект его стоит переписать: добавить
путь к библиотеке компонентов, правила именования, запрет на новые зависимости.

## Известные дыры, которые, возможно, придётся закрыть

Перечислены в README в разделе «Известные ограничения». Если какая-то мешает именно
вашему проекту — доработка идёт в `src/pull/**` (нормализация) или `src/mcp/**` (чтение).
Формат меняется только через раздел «Предложения» в [docs/CONTRACT.md](CONTRACT.md):
поля добавляются необязательными, чтобы не ломать уже выгруженные макеты.

## Как проверить, что не сломали

```bash
npm run typecheck
npm test
figma-vault check --vault <хранилище>
```

`check` поднимает настоящий MCP-сервер дочерним процессом и валидирует каждый `doc.json`
против контракта. Код возврата 1 при проблемах.

Для визуальной сверки: `npm run dev` поднимает локальный просмотр, страница `/compare/<имя>`
показывает восстановленную вёрстку и эталонный рендер Figma рядом, с синхронной прокруткой
и режимом наложения.
