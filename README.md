# figma-vault

Локальное хранилище макетов Figma для AI-агентов.

Макет выгружается из Figma **один раз**, нормализуется и ложится на диск. После этого
Claude Code, Codex и любой другой MCP-клиент читают его сколько угодно — без обращений
к Figma, без токена и без лимитов.

```
один разработчик:  figma-vault add <ссылка>  →  хранилище  →  git commit
вся остальная команда:  агент читает через MCP, токен не нужен
```

## Какую проблему решает

У Figma MCP жёсткие лимиты обращений. Агент во время вёрстки лезет в макет постоянно:
уточнить отступ, перепроверить цвет, посмотреть размер шрифта — десятки обращений за
одну сессию. Лимит выбивается быстро, и работа встаёт.

Здесь число обращений к Figma **не зависит от активности агента**: оно фиксировано
и тратится один раз, в момент выгрузки.

|  | Figma Dev Mode MCP | figma-vault |
|---|---|---|
| кто ходит в Figma | агент, во время работы | CLI, однократно |
| сколько обращений | пропорционально работе агента | фиксировано на макет |
| нужен ли токен читающему | да, каждому | нет |
| работает офлайн | нет | да |

Отдельный эффект: макет становится артефактом репозитория. Разработчику без доступа
к Figma-файлу (нет лицензии, нет прав, не выдали токен) макет доступен полностью.

## Установка

Требуется Node.js 22+.

```bash
npm i -g figma-vault
# или из git, если внутренний реестр: npm i -g github:<организация>/figma-vault
```

### Вариант 1. В проект

```bash
figma-vault init
```

Создаёт `.figma-vault/`, добавляет сервер в `.mcp.json` проекта (чужие записи не трогает),
дописывает `.env` в `.gitignore` и кладёт слэш-команду `/figma` для Claude Code.

Флаг `--no-command` пропускает установку `/figma`. Нужен, когда в команде свой порядок работы
и связка «выгрузил и сразу сверстал» в него не укладывается: агенту остаются только
инструменты чтения `vault_*`.

### Вариант 2. Без единого файла в репозитории

```bash
figma-vault init --global
```

Хранилище уезжает в `~/.figma-vault/`, сервер регистрируется в пользовательском конфиге
агента. Рабочий репозиторий о существовании инструмента не знает. Нужно, когда в проект
нельзя добавлять зависимости и конфиги.

## Использование

```bash
figma-vault add "https://figma.com/design/КЛЮЧ/Проект?node-id=127-4532"
```

Ссылка берётся в Figma: правая кнопка по фрейму → **Copy link to selection**.

```bash
figma-vault limits "<ссылка>"   # проверить лимиты Figma ДО выгрузки
figma-vault list                # что уже выгружено
figma-vault check               # проверить, что цепочка работает
figma-vault demo                # демо-макет без токена
```

### Сколько это стоит в обращениях к Figma

Лимиты REST API считаются по токену и зависят от тарифа и типа места. Заранее узнать
их нельзя, поэтому перед первой выгрузкой:

```bash
figma-vault limits "<ссылка на фрейм>"
```

Два запроса — те же, что сделала бы выгрузка — и ответ, пройдёт ли она:

```
[ OK ]  Чтение структуры  /v1/files/:key/nodes — HTTP 200
[ЛИМИТ] Рендер картинок   /v1/images/:key — HTTP 429
        освободится примерно через 5 сут
```

Полная выгрузка одного экрана стоит **три запроса**, измерено на реальном макете
из 332 узлов:

| | запросов |
|---|---|
| структура (`/v1/files/:key/nodes`) | 1 |
| скриншот фрейма (`/v1/images`) | 1 |
| растровые картинки (`/v1/images`, пачками по 40) | 1 на 40 картинок |
| иконки и векторы | **0** |

Иконки не рендерятся: их контуры приходят вместе со структурой, SVG собирается локально.
На том же макете это 141 иконка за ноль запросов. Поэтому **стоимость выгрузки не зависит
от того, сколько в макете иконок**.

Дальше агент читает макет сколько угодно — запросов к Figma не будет вообще.

В Claude Code после `init` доступна одна команда:

```
/figma <ссылка на фрейм>
```

Она выгружает макет, читает его через MCP и верстает по конвенциям проекта.

## Проверка без токена Figma

Токен нужен только для выгрузки новых макетов. Чтение работает без него — это штатный
режим для всех, кроме одного человека. Поэтому установку можно проверить целиком,
не создавая токен:

```bash
figma-vault init && figma-vault demo && figma-vault check
```

```
[ OK ] .mcp.json — сервер figma-vault зарегистрирован
[ OK ] Хранилище — .figma-vault/, макетов: 1
[ OK ] Макет EXAMPLE1234_1_1 — узлов: 29
[ OK ] MCP-сервер — инструментов: 6 (vault_list, vault_get_doc, …)
[ВНИМ] FIGMA_TOKEN — не задан — читать макеты можно, выгружать новые нельзя
```

`check` поднимает настоящий MCP-сервер дочерним процессом и здоровается с ним по протоколу.
Код возврата 1 при реальных проблемах — годится для CI.

## Токен

Figma → Settings → Security → Personal access tokens → Generate new token.
Scope нужен один: **File content → Read-only**.

Кладётся в `.env` строкой `FIGMA_TOKEN=figd_...` или в переменную окружения пользователя.

## Что агент получает

MCP-сервер даёт шесть read-only инструментов:

| инструмент | что отдаёт |
|---|---|
| `vault_list` | список выгруженных макетов |
| `vault_get_doc` | дерево макета, `maxDepth` обрезает по глубине |
| `vault_get_node` | поддерево одного узла |
| `vault_search` | поиск узлов по имени и тексту |
| `vault_get_tokens` | цвета, типографика, эффекты |
| `vault_get_asset` | картинка или иконка |

Дерево нормализовано: auto-layout превращён в `mode: row|column` с `gap` и `padding`,
координаты относительны родителю, стили и текст приведены к предсказуемому виду.
Сырой ответ Figma сохраняется рядом в `raw.json` для отладки.

На реальном макете нормализация ужимает дерево примерно в 7 раз:

```
raw.json   1.9 МБ   сырой ответ Figma
doc.json   256 КБ   то, что читает агент
```

Это не только экономия места — агент, читающий 256 КБ вместо двух мегабайт, восстанавливает
интерфейс заметно точнее.

## Формат хранилища

```
<хранилище>/
  index.json                 список макетов
  <docId>/
    doc.json                 нормализованное дерево — главный артефакт
    raw.json                 сырой ответ Figma
    screenshot.png           рендер макета целиком
    assets/                  иконки и картинки
```

Схема `figma-vault/doc@0` описана в [docs/CONTRACT.md](docs/CONTRACT.md) и проверяется
строгим валидатором. `doc.json` самодостаточен: MCP-сервер не обращается ни к `raw.json`,
ни к сети.

## Известные ограничения

Перечислено честно — это MVP, и вот что он пока не умеет.

- **Лимит рендера картинок.** `/v1/images` у Figma выбивается раньше, чем чтение структуры,
  и блокируется надолго — счёт идёт на сутки. Иконки эту проблему больше не создают
  (собираются локально), но скриншот фрейма и растровые картинки идут через этот эндпоинт.
  Клиент повторяет запрос по `Retry-After` до трёх раз и не засыпает дольше минуты;
  если Figma просит ждать сутками, выгрузка **сохраняет структуру** и пишет причину
  в предупреждения, а не падает целиком. Проверяйте `figma-vault limits` до выгрузки.
- **Градиенты теряются.** Узел с градиентной заливкой приезжает без неё.
- **Разноцветные фрагменты внутри одного текста теряются.** Если в заголовке одно слово
  выделено цветом, агент увидит текст одним цветом.
- **Скрытые узлы выбрасываются.** На реальном макете это треть дерева — там лежат
  опциональные слоты компонентов. Предложение оставлять их с пометкой `hidden` готовится.

## На чём проверялось

Фикстура в репозитории синтетическая: 29 узлов, нужна чтобы поставить инструмент
и убедиться, что цепочка работает без токена Figma.

Точность проверялась отдельно, на двух настоящих макетах — их содержимое в репозиторий
не выкладывается. Измеренное на продуктовом экране интерфейса из 332 узлов, глубина 15:

| проверка | результат |
|---|---|
| тексты макета в восстановленной вёрстке | 41 из 41 |
| иконки | 15 из 15, битых ссылок 0 |
| потребовалось заглушек | 1 (растровый аватар) |
| обращений к Figma при выгрузке | 3 |
| `doc.json` против контракта | проходит |

Что при этом **не проверено**: попиксельное совпадение. Сравнение с эталонным рендером
Figma делается глазами через `npm run dev` → `/compare/<имя>`; автоматической структурной
сверки восстановленной вёрстки с `doc.json` пока нет.

Найденные на реальных макетах расхождения, уже исправленные: терялся `letterSpacing`
(в дизайн-системах он ненулевой почти везде, 0.05–0.12px, и без него вёрстка выглядит
«не тем шрифтом»); порядок `children` принимался за визуальный, хотя это z-order.

## Чего инструмент не делает намеренно

Не SaaS, не замена Figma, не real-time sync. Нет авторизации, биллинга, команд
и пользователей. Нет серверной части: MCP — дочерний процесс агента на машине
разработчика, общение через stdio. Разворачивать что-либо на сервере не нужно.

## Разработка

```bash
npm install
npm test          # 28 тестов
npm run typecheck
npm run dev       # локальный просмотр восстановленной вёрстки и сравнение с макетом
```

Проект пишут два AI-агента параллельно по протоколу из [AGENTS.md](AGENTS.md):
разделение зон, доска задач, журнал переписки. История коммитов помечена авторами.
